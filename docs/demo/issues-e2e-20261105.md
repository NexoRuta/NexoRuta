## Issues

### E2E-DMO-01 — Commerce no puede recuperar el enlace de seguimiento en GCP Production

- **Prioridad:** alta; bloquea la parte de seguimiento de WEB-04.
- **Tipo:** autorización/configuración de aplicación.
- **Estado:** confirmado por inspección; no reproducido contra la API remota porque respondió 503.

**Descripción:** Commerce llama a GET /api/envios/{envioId}/seguimiento desde MisEnvios.razor mediante EnviosApiClient.ObtenerSeguimientoAsync. EnlaceSeguimientoController requiere la política seguimiento-demo. En Program.cs, esa política solo satisface su aserción cuando el entorno es Development. deploy/gcp/compose.yaml fija ASPNETCORE_ENVIRONMENT: Production para la API. Por lo tanto, una sesión autenticada de Commerce en GCP no puede recuperar el enlace por esa ruta.

**Pasos para reproducir:** iniciar sesión en Commerce en Production, abrir un envío propio con enlace vigente y solicitar “Ver seguimiento”. La llamada protegida debería responder 403 para un usuario autenticado que sí pertenece al tenant.

**Esperado:** un comercio autorizado puede recuperar únicamente el enlace vigente de un envío de su organización en Production, con las mismas garantías de aislamiento, secreto y auditoría; los demás tenants siguen rechazados.

**Criterio de cierre:** prueba de autorización en configuración Production-like para Commerce del tenant propietario y para un tenant ajeno, además de una verificación HTTP autenticada. No cambiar GCP a Development ni quitar autorización como workaround.

**Referencias:** frontend/src/NexoRuta.Commerce/Components/Features/Envios/Pages/MisEnvios.razor; frontend/src/NexoRuta.ApiClient/Features/Envios/Clients/EnviosApiClient.cs; backend/src/NexoRuta.Api/Features/Seguimiento/Controllers/EnlaceSeguimientoController.cs; backend/src/NexoRuta.Api/Program.cs; deploy/gcp/compose.yaml.

**Descripción:** la publicación de imágenes terminó correctamente, pero el paso de OpenTofu apply falló. **Criterio de cierre:** provisionar la identidad y el secreto por el procedimiento seguro aprobado, o hacer explícita la dependencia opcional en IaC para que start no aplique permisos de un recurso ausente.
